# pupas-lupas-history-bot

Telegram-бот «#MemeThrowback». За один запуск он публикует в канал один старый мем, вышедший в этот же день N лет назад, и завершается. Запуски идут по расписанию примерно 5–6 раз в день (расписание живёт вне репозитория).

- [docs/spike-bot-only.md](docs/spike-bot-only.md) — что бот может и чего не может без пользовательского аккаунта (проверено на Telegram).

## Устройство

- Пакет `throwback/`, запуск — `python -m throwback`; `app.py` — обёртка для старого способа запуска.
- Чистое ядро без Telethon-клиентов: `model.py` (`Post`, `Group`, `MediaKind`, `Entity`), `dates.py`, `selection.py` (группировка, фильтры, ранжирование), `captions.py` (подпись репоста: текст оригинала, если в нём не одни хэштеги, + ссылка с годом), `runner.py` (`post_throwback` поверх протокола `Source`), `memery.py`, `config.py`.
- `telegram.py` — единственное место, где живёт Telethon: перевод сообщений в `Post` и класс `Channel` (пользователь читает историю и реакции, бот получает свои копии сообщений по id и отправляет медиа по ссылке). `__main__.py` поднимает клиенты. Пользовательский аккаунт нужен: бот не видит реакций, а по ним идёт ранжирование.
- Конфиг: `.env.defaults` (в git) ← `.env` (секреты, не в git) ← переменные окружения. Список переменных — в `docs/architecture.md`.
- Состояние в `storage/` (в `.gitignore` и `.dockerignore`): `sessions/*.session` и `memery.json`.

## Команды

Зависимости управляются через [uv](https://docs.astral.sh/uv/), версии зафиксированы в `uv.lock`.

```bash
uv sync                          # .venv с зависимостями и dev-инструментами
uv run pytest                    # тесты, без сети
uv run ruff check && uv run ruff format --check
uv run pyright
uv run python -m throwback --dry-run  # выбрать пост и напечатать его; пользователь только читает канал
uv run python -m throwback       # ВНИМАНИЕ: реальный вход в аккаунты и публикация
docker compose run --rm bot      # то же самое в контейнере, storage/ монтируется
```

CI ([.github/workflows/build.yml](.github/workflows/build.yml)) запускает ruff, pyright и pytest на каждый push и PR; push в `main` после проверок публикует образ в GHCR.

## Правила

- С машины разработчика (РФ) Telegram доступен только через SOCKS5 `127.0.0.1:2080` (`TELEGRAM_PROXY` в локальном `.env`); на сервере прокси не нужен. Сетевым командам ставь короткие тайм-ауты (1–3 минуты); FloodWait у бота на `getMessages` наступает после ~4 запросов подряд.
- **Не запускай бота и не делай вызовы Telegram без явной просьбы.** Код входит в настоящий пользовательский аккаунт и бота. Без `TELEGRAM_TEST_CHAMBER_ID` он публикует в боевой канал; с ним (так настроен локальный `.env`) шлёт в тестовую группу, не пишет memery и не ставит `reply_to`. `--dry-run` бота не запускает и ничего не отправляет.
- Коды выхода (0 — опубликовано, 3 — нечего публиковать, 1 — ошибка) — часть интерфейса: cron и человек смотрят на них.
- `storage/sessions/*.session` — это доступ к аккаунтам. Не читай, не печатай и не копируй их; `.env` тоже не выводи. Для экспериментов бот может войти по токену во временную `StringSession`.
- Репосты публикуются в тот же канал, откуда берутся мемы. Любая логика выбора должна исключать собственные посты бота (у них подпись `#MemeThrowback`).
- Фильтры и скоринг применяй к группе (альбому), а не к отдельному сообщению.
- Смещения форматирования (`Entity.offset/length`) — в единицах UTF-16, как в Telegram: эмодзи вне BMP занимают две. Меняя или обрезая текст, двигай и обрезай entities вместе с ним (см. `captions.truncate`).
- Новая логика — в чистом ядре с тестами; в `telegram.py` только перевод данных и вызовы Telethon.
- Код, комментарии и сообщения коммитов — на английском, документация в `docs/` — на русском.
