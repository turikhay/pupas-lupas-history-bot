# Как лучше переписать

Рекомендации по итогам [review.md](review.md). Порядок задан так, чтобы бот работал между этапами и каждый шаг можно было выкатить отдельно.

## Главные решения

### 1. Обойтись без пользовательского аккаунта — отклонено

> **Решение (2026-10-15): пользовательский аккаунт остаётся.** Ранжирование по реакциям нужно, а бот их не видит (пользователь видит; см. [spike-bot-only.md](spike-bot-only.md)). Роли разделены так: пользователь читает историю и реакции, бот отправляет медиа по ссылке (этап 3, проверено). Индекс по id для бота не нужен; ниже — исходный вариант, оставленный для истории.

Сейчас пользовательская сессия — самое хрупкое место. Она даёт полный доступ к личному аккаунту, может слететь, требует интерактивного входа, а автоматизация под ней рискует блокировкой. Нужна она только для чтения истории: боту запрещены `messages.getHistory` и `messages.search`.

Зато боту доступен `channels.getMessages` — получение сообщений **по id**, до 100 за запрос (в Telethon это `bot.get_messages(channel, ids=[…])`). В канале id растут монотонно вместе с датой, так что историю можно обойти по id:

- **Индекс.** Один раз пройти все id от 1 до последнего пачками по 100 и сохранить `id → (date, grouped_id, тип медиа, автор, подпись)` в SQLite. При 50 тыс. сообщений это около 500 запросов, то есть минуты с учётом FloodWait. Дальше на каждом запуске догружать id после максимального известного, пока не пойдут пустые пачки (верхнюю границу подсказывает и id последнего собственного репоста).
- **Выбор.** Кандидаты за нужный день берутся запросом к индексу. Затем их сообщения запрашиваются заново через `get_messages(ids=…)`, чтобы получить свежие реакции, просмотры и пересылки и заметить удалённые посты.
- **Отправка** по ссылке, без скачивания: `bot.send_file(channel, [m.media for m in group], caption=…)`.

Альтернатива без индекса — бинарный поиск границ дня по id на каждом запуске (около 10–15 запросов на год). Это проще, но индекс всё равно пригодится для статистики, взвешенного выбора года и хранения состояния.

**Что проверить прототипом (около часа, на тестовом чате):**

1. `bot.get_messages(channel, ids=range(a, a + 100))` для постов 2018 года возвращает `date`, `grouped_id`, `media`, `reactions`, `views`, `forwards`.
2. `bot.send_file(test_chat, [m.media for m in album], caption=…)` отправляет альбом без скачивания, и GIF, видео и спойлеры остаются собой.
3. Полный проход по id: сколько занимает, бывает ли FloodWait.

Если пункт 1 не подтвердится, пользовательский аккаунт оставляем только для построения и обновления индекса, а отправку всё равно переводим на бота по ссылке. Пункт 2 полезен в любом случае.

### 2. Чистое ядро и тонкий слой Telegram

Вся логика (даты, годы, группировка, фильтры, скоринг) работает с собственными dataclass'ами, а не с объектами Telethon. Тогда её можно покрыть тестами без сети. Telethon остаётся в одном модуле, который умеет «получить сообщения по id», «превратить Message в Post» и «отправить группу».

```python
@dataclass(frozen=True)
class Post:
    id: int
    grouped_id: int | None
    date: datetime  # aware, UTC
    kind: MediaKind  # photo / video / gif / sticker / voice / document / none
    text: str
    author: str | None
    reply_to: int | None
    reactions: dict[str, int]  # "👍" → 12, "custom:<id>" → 3, "paid" → 50
    views: int | None
    forwards: int | None


@dataclass(frozen=True)
class Group:
    key: int  # минимальный id в группе — то же пространство, что id сообщений
    posts: tuple[Post, ...]
```

Ключ группы — минимальный id сообщения, а не `grouped_id`: он стабилен, понятен и лежит в одном пространстве с `reply_to`.

### 3. Состояние в SQLite

Встроенный `sqlite3`, один файл в `storage/`, транзакции вместо перезаписи JSON.

```sql
CREATE TABLE posts (            -- индекс канала
  id INTEGER PRIMARY KEY,
  grouped_id INTEGER,
  date TEXT NOT NULL,           -- ISO, UTC
  kind TEXT NOT NULL,
  author TEXT,
  text TEXT
);
CREATE INDEX posts_date ON posts(date);

CREATE TABLE reposts (          -- что уже опубликовано
  group_key INTEGER PRIMARY KEY,
  sent_ids TEXT NOT NULL,       -- id наших сообщений, чтобы не репостить себя
  target_date TEXT NOT NULL,
  posted_at TEXT NOT NULL
);

CREATE TABLE legacy_memery (id INTEGER PRIMARY KEY);  -- импорт memery.json как есть
```

Миграция: `memery.json` целиком переносится в `legacy_memery`. Группа считается уже опубликованной, если её `group_key` есть в `reposts` или если её `grouped_id` либо id любого её сообщения есть в `legacy_memery`.

### 4. Свои посты определяются надёжно

Пост считается собственным, если выполнено любое из условий: его id есть в `reposts.sent_ids`; подпись группы содержит `#MemeThrowback`; автор входит в список `IGNORE_AUTHORS`. Это закрывает пункт 1 из обзора.

### 5. Отбор и ранжирование на уровне группы

1. Найти кандидатов за день: все группы с датой в `[полночь, полночь + 1 день)` в часовом поясе канала.
2. Отбросить группы, которые уже публиковались, и собственные посты.
3. Отфильтровать группы целиком: все элементы допустимого типа (фото, видео, GIF), по тексту всех подписей (среда — регуляркой по словоформам).
4. Оценить. Для начала подойдёт такая формула:
   - `reactions = Σ позитивных − Σ негативных` (кастомные эмодзи считаются позитивными, ⭐ с повышенным весом);
   - `score = (reactions + 3 · forwards) / max(views, 1)`, сравнение только внутри одного дня;
   - если данных нет совсем, выбор случайный.

   Веса лучше подобрать по истории из индекса, а не на глаз.
5. Год можно выбирать не равновероятно, а взвешивать по наличию хороших кандидатов и не повторять год предыдущего запуска (он есть в `reposts`).

### 6. Режимы запуска

```
python -m throwback run                     # обычный запуск по расписанию
python -m throwback run --dry-run           # выбрать и напечатать пост и подпись, ничего не отправлять и не писать
python -m throwback run --target test       # отправить в тестовый чат; состояние не пишется, reply_to не ставится
python -m throwback run --date 2026-02-29   # прогнать для другой даты (с --dry-run)
python -m throwback sync                    # догрузить индекс
python -m throwback migrate-memery storage/memery.json
```

Подпись формировать через `parse_mode="html"`: в нём есть `<u>`, `<i>`, `<a>`.

### 7. Эксплуатация

- **Один процесс — один репост**, как сейчас: такой режим проще и устойчивее долгоживущего. Расписание держать в репозитории: `deploy/throwback.timer` и `throwback.service` для systemd или строка cron в README. Запуск через `flock`, чтобы процессы не накладывались.
- **Коды выхода:** 0 — опубликовано, 2 — нечего публиковать, 1 — ошибка.
- **Алерты:** dead-man's switch (например, ping на healthchecks.io после успешного запуска) или отправка ошибки ботом в личку админу.
- **Без интерактива:** проверять `is_user_authorized()` и сразу падать с понятным сообщением, а не ждать `input()`. Если от пользовательского аккаунта удастся отказаться, проблема исчезнет.
- **Клиенты** создаются внутри `async def main()` через `async with`, запуск — `asyncio.run(main())`. Ничего не выполняется при импорте.

### 8. Инструменты

- `pyproject.toml` и lock-файл (uv), одна версия Python локально и в Docker (3.12 или 3.13).
- Telethon обновить до актуальной 1.x (1.45.0 на 2026-09-10). Pillow, если Telethon он больше не нужен (при отправке по ссылке не нужен), убрать; иначе обновить. Ручные пины транзитивных зависимостей убрать.
- `ruff` и `pyright` (в `.vscode/settings.json` уже стоит `basic`), `pytest`.
- CI: lint, type-check и тесты, затем сборка образа.
- Docker: добавить `storage` в `.dockerignore`, `CMD` в exec-форме, непривилегированный пользователь.
- `chmod 600 storage/sessions/*.session`.

## Структура

После этапа 2 пакет лежит в корне (`throwback/`, без `src/`): это приложение, а не библиотека, и `python -m throwback` работает из корня без установки. Уже есть модули, отмеченные ✅; остальные появятся на следующих этапах.

```
pyproject.toml, uv.lock  ✅
throwback/
  __main__.py      ✅ точка входа; позже CLI: run / sync / migrate-memery
  config.py        ✅ настройки из env, с валидацией
  model.py         ✅ Post, Group, MediaKind — без Telethon
  dates.py         ✅ сегодня в TZ, N лет назад, доступные годы
  selection.py     ✅ группировка, фильтры, скоринг
  runner.py        ✅ один запуск поверх протокола Source
  memery.py        ✅ JSON-список опубликованного (заменит store.py)
  telegram.py      ✅ Telethon: to_post, Channel (позже fetch_by_ids, send по ссылке)
  store.py         SQLite: posts, reposts, legacy_memery
  index.py         синхронизация индекса по id
tests/             ✅ даты, фильтры, ранжирование, перевод сообщений Telethon, memery, конфиг, runner
deploy/
  throwback.service
  throwback.timer
```
