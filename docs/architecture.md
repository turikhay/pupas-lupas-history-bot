# Как бот работает сейчас

Описание поведения кода на коммите `6695ba4` (2026-09-17). Здесь описано, что код делает на самом деле, а не что задумывалось. Проблемы разобраны в [review.md](review.md), план переписывания — в [rewrite-plan.md](rewrite-plan.md).

## Назначение

За один запуск бот публикует в канал один старый мем, вышедший в тот же календарный день N лет назад, с подписью `[ГОД](ссылка на оригинал) #MemeThrowback`. Репост уходит **в тот же канал**, из которого берётся история. Запуски повторяются раз в несколько часов (расписание живёт вне репозитория).

## Файлы

| Файл | Что делает |
|---|---|
| [app.py](../app.py) | Почти всё: конфиг, два клиента Telethon, выбор даты, сбор постов, репост. Работа начинается прямо при импорте модуля. |
| [filters.py](../filters.py) | `can_be_reposted`: можно ли репостить группу. Без побочных эффектов, импортируется отдельно. |
| [dateutils.py](../dateutils.py) | «Сегодня» в нужном часовом поясе, та же дата N лет назад (29 февраля → 28-е), полночь даты. |
| [message.py](../message.py) | `GroupedMessages` — альбом или одиночный пост. |
| [sorter.py](../sorter.py) | Ранжирование по эмодзи-реакциям. |
| [supported_media.py](../supported_media.py) | Проверка «фото или документ». |
| [memery/](../memery/) | «Memery» — список уже запощенного: JSON-массив id в одном файле. |

## Два аккаунта

- `user` — пользовательская сессия (`storage/sessions/user.session`). Нужна потому, что в MTProto бот не может читать историю канала (`messages.getHistory`, `messages.search`). Через неё бот читает историю и скачивает медиа.
- `bot` — бот по `TELEGRAM_BOT_TOKEN` (`storage/sessions/bot.session`). Через него идёт публикация.

## Алгоритм одного запуска

1. В кандидаты попадают все значения «лет назад» `k ≥ 1`, для которых та же дата `k` лет назад не раньше `TELEGRAM_SEARCH_DATE_START` (`available_years` в [dateutils.py](../dateutils.py)).
2. Цикл: выбрать случайное `k`, убрать его из множества, `target_date = сегодня − k лет`.
3. `collect_messages_at_date` ([app.py:107](../app.py#L107)):
   - найти последний фото/видео-пост строго раньше полуночи `target_date` (`get_messages` с `InputMessagesFilterPhotoVideo`);
   - идти от него вперёд (`iter_messages(reverse=True, offset_id=…, limit=100)`) и брать сообщения с датой в `[полночь, полночь + 1 день)`;
   - все сообщения дня собираются в группы по `grouped_id` (альбом) или по `id`.
4. Каждая группа проверяется `can_be_reposted` ([filters.py](../filters.py)), непрошедшие отбрасываются.
5. `sort_by_best` ([sorter.py](../sorter.py)): оценка группы — сумма эмодзи-реакций **первого** сообщения (+1 за каждую реакцию, −1 за 👎 💩 🥱 🤔). Группы с отрицательной оценкой отбрасываются, при равной оценке порядок случайный. Если у всех групп оценка 0, список просто перемешивается.
6. Берётся первая группа, которой нет в memery. Пользователь скачивает её медиа в `/tmp/`, бот отправляет их альбомом с подписью, `silent=True` и `reply_to` = id сообщения, на которое отвечал оригинал.
7. В memery записываются `group.id` (это `grouped_id` альбома или `id` сообщения) и `reply_to`.
8. Если за выбранный год постить нечего, бот переходит к следующему году. Когда годы закончились, пишется `logging.error`, и процесс завершается с кодом 0.

## Фильтры (`can_be_reposted`)

Применяются к группе целиком ([filters.py](../filters.py)): если не проходит хотя бы одно сообщение альбома, отбрасывается весь альбом. Текстовые проверки смотрят на подписи всех элементов вместе.

- собственные репосты бота: подпись автора (`post_author`) входит в `TELEGRAM_IGNORE_AUTHOR` или в подписях группы есть `#MemeThrowback`. Хэштег нужен потому, что подпись автора меняется вместе с именем бота;
- нет медиа, или медиа не фото и не документ;
- документ с mime `image/webp` (стикер);
- сегодня не среда, а в подписях есть слово «среда» в любой форме или «wednesday» (`wednesday_pattern`, только целые слова). «Окружающая среда» тоже совпадает, «среди» и «средство» — нет.

## Конфигурация

Значения накладываются по порядку: `.env.defaults` (лежит в git) ← `.env` (локальный, с секретами) ← переменные окружения.

| Переменная | Смысл |
|---|---|
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | приложение с my.telegram.org |
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHANNEL_ID` | канал в формате `-100…` (в таком виде его понимает `get_entity` у пользователя) |
| `TELEGRAM_SEARCH_TIMEZONE` | часовой пояс для «сегодня» и границ дня |
| `TELEGRAM_SEARCH_DATE_START` | дата начала канала |
| `TELEGRAM_MEMERY_FILE` | путь к JSON со списком запощенных id |
| `TELEGRAM_IGNORE_AUTHOR` | подписи авторов через запятую, посты с которыми не репостятся (старое и новое имя бота) |
| `TELEGRAM_TEST_CHAMBER_ID` | необязательная; если задана, бот шлёт в этот чат вместо канала. Это id обычной группы (`PeerChat`), супергруппа не подойдёт. Memery при этом **всё равно записывается**. |
| `TELEGRAM_SESSION_DIR` | каталог с `.session` |

## Состояние

`storage/` лежит в `.gitignore` и монтируется в контейнер:

- `sessions/user.session` — полный доступ к пользовательскому аккаунту;
- `sessions/bot.session`;
- `memery.json` — массив int. Файл должен существовать заранее (с содержимым `[]`), иначе первый же `is_posted_already` упадёт с `FileNotFoundError`. В локальной копии его сейчас нет.

## Сборка и запуск

- GitHub Actions ([build.yml](../.github/workflows/build.yml)): каждый push в `main` собирает образ и публикует его в `ghcr.io/<owner>/<repo>`. Тестов и линтеров в CI нет.
- [compose.yaml](../compose.yaml): один сервис с томом `./storage`, без расписания и без restart-политики. Процесс делает один репост и завершается.
- Расписание «раз в несколько часов» задано вне репозитория (cron или таймер на хосте).
- Первый вход пользователем интерактивный: Telethon спросит телефон и код. Если сессия слетела, неинтерактивный запуск упадёт на `input()`.
- Версия Python: в Docker 3.10.12, в локальном `.venv` 3.12.3.
