# Как бот работает сейчас

Описание того, что код делает на самом деле, а не что задумывалось. Проблемы разобраны в [review.md](review.md), план переписывания — в [rewrite-plan.md](rewrite-plan.md), возможности бота без пользовательского аккаунта — в [spike-bot-only.md](spike-bot-only.md).

## Назначение

За один запуск бот публикует в канал один старый мем, вышедший в тот же календарный день N лет назад, с подписью `[ГОД](ссылка на оригинал) #MemeThrowback`. Репост уходит **в тот же канал**, из которого берётся история. Запуски идут примерно 5–6 раз в день; расписание живёт вне репозитория.

## Файлы

Код лежит в пакете [throwback/](../throwback/). Всё, кроме `telegram.py` и `__main__.py`, работает без Telethon-клиентов и покрыто тестами в [tests/](../tests/).

| Файл | Что делает |
|---|---|
| [\_\_main\_\_.py](../throwback/__main__.py) | Точка входа `python -m throwback [--dry-run]`: читает конфиг, поднимает клиенты Telethon, выбирает режим, запускает `post_throwback` и превращает результат в код выхода. |
| [runner.py](../throwback/runner.py) | `post_throwback`: выбор года, фильтрация, ранжирование, репост, запись в memery. Работает через протоколы `History` (чтение) и `Publisher` (публикация), в тестах их заменяют фейки. `DryRun` — публикатор, который только печатает. |
| [telegram.py](../throwback/telegram.py) | Адаптер Telethon: `to_post` (сообщение → `Post`, тип медиа по атрибутам документа), `ChannelHistory.fetch_day` (посты за день через пользователя), `BotPublisher.repost` (бот получает свои копии сообщений по id и отправляет медиа по ссылке). |
| [selection.py](../throwback/selection.py) | Группировка в альбомы, `can_be_reposted`, `score`, `rank`. |
| [captions.py](../throwback/captions.py) | Подпись репоста: исходный текст как есть, если в нём есть что-то кроме хэштегов (с форматированием, в лимите 1024), и ссылка на оригинал с годом. |
| [model.py](../throwback/model.py) | `Post`, `Group`, `MediaKind`, `Entity` (форматирование текста) — данные без Telethon. |
| [dates.py](../throwback/dates.py) | «Сегодня» в нужном часовом поясе, та же дата N лет назад (29 февраля → 28-е), доступные годы, полночь даты. |
| [memery.py](../throwback/memery.py) | «Memery» — список уже опубликованного: JSON-массив id в одном файле. |
| [config.py](../throwback/config.py) | Чтение и проверка настроек. |
| [app.py](../app.py) | Обёртка для тех, кто по-прежнему запускает `python3 app.py`. |

## Два аккаунта

- `user` — пользовательская сессия (`storage/sessions/user.session`). Нужна потому, что в MTProto бот не может читать историю канала (`messages.getHistory`, `messages.search`) и не видит реакций, а по реакциям идёт ранжирование. Через неё бот только читает.
- `bot` — бот по `TELEGRAM_BOT_TOKEN` (`storage/sessions/bot.session`). Получает выбранные сообщения по id (`channels.getMessages`) и публикует их медиа по ссылке. Ссылки на файлы привязаны к аккаунту, поэтому бот запрашивает собственные копии сообщений.

## Алгоритм одного запуска

1. В кандидаты попадают все значения «лет назад» `k ≥ 1`, для которых та же дата `k` лет назад не раньше `TELEGRAM_SEARCH_DATE_START` (`available_years`).
2. Цикл: выбрать случайное `k`, убрать его из списка, `target_date = сегодня − k лет`.
3. `ChannelHistory.fetch_day`: пользователь идёт назад от конца дня (`iter_messages(offset_date=полночь следующего дня)`) до первого сообщения раньше полуночи `target_date`. Служебные сообщения пропускаются, остальные разворачиваются в порядок от старых к новым. Лимита нет, насыщенный день не обрезается.
4. Сообщения собираются в группы по `grouped_id` (альбом) или по `id`; каждая группа проверяется `can_be_reposted`.
5. `rank`: оценка группы считается по реакциям **первого** сообщения: +1 за каждую реакцию, −1 за 👎 💩 🥱 🤔, +10 за каждую платную звезду. Кастомные эмодзи считаются как обычный эмодзи, который они изображают (`alt` из `messages.getCustomEmojiDocuments`; запрашивается пользователем один раз за запуск и кешируется). Группы с отрицательной оценкой отбрасываются, при равной оценке порядок случайный. Если у всех групп оценка 0, список просто перемешивается. Для 2017–2021 реакций почти нет, и выбор там фактически случайный — так и задумано.
6. Берётся первая группа, которой нет в memery. Бот получает её сообщения по id и отправляет их медиа по ссылке (ничего не скачивается и не перекодируется: те же файлы, GIF остаются GIF) с подписью, `silent=True` и `reply_to` = id сообщения, на которое отвечал оригинал.
7. Подпись (`build_caption`):
   - берутся подписи всех элементов группы вместе с форматированием (жирный, курсив, ссылки-тексты и т. п.; ссылки, упоминания и хэштеги Telegram распознаёт сам, кастомные эмодзи становятся обычными);
   - хэштеги (`#тег`, `#тег@канал`; `#1` и `C#` хэштегами не считаются) нужны только для решения: если кроме них в тексте только пробелы и знаки препинания (`#shrek #mashup`), текст не переносится. Эмодзи считаются текстом;
   - иначе текст переносится как есть, вместе с хэштегами (`Skyrim #gaming`), а через пустую строку идёт `ГОД #MemeThrowback`, где год — ссылка на оригинал. Год считается в часовом поясе канала;
   - всё вместе укладывается в 1024 единицы UTF-16 (лимит подписи для ботов): длинный текст обрезается по пробелу, если он не дальше 30 символов, и заканчивается на «…».
8. В memery записываются ключ группы (`grouped_id` альбома или `id` сообщения) и `reply_to`.
9. Если за выбранный год постить нечего, бот переходит к следующему году. Когда годы закончились, пишется `logging.error`, и процесс завершается с кодом 0.

## Фильтры (`can_be_reposted`)

Применяются к группе целиком: если не проходит хотя бы одно сообщение альбома, отбрасывается весь альбом. Текстовые проверки смотрят на подписи всех элементов вместе.

- Собственные репосты бота: подпись автора (`post_author`) входит в `TELEGRAM_IGNORE_AUTHOR` или в подписях группы есть `#MemeThrowback`. Хэштег нужен потому, что подпись автора меняется вместе с именем бота.
- Тип медиа: проходят только фото, видео и GIF (`REPOSTABLE_MEDIA`). Текст без медиа, стикеры, кружочки, голосовые, аудио, файлы и превью ссылок не проходят; альбом проходит, только если все его элементы — фото, видео или GIF.
- Сегодня не среда, а в подписях есть слово «среда» в любой форме или «wednesday» (`wednesday_pattern`, только целые слова). «Окружающая среда» тоже совпадает, «среди» и «средство» — нет.

## Конфигурация

Значения накладываются по порядку: `.env.defaults` (лежит в git) ← `.env` (локальный, с секретами) ← переменные окружения. Если обязательной переменной нет, бот падает со списком недостающих.

| Переменная | Смысл |
|---|---|
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | приложение с my.telegram.org |
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHANNEL_ID` | канал в формате `-100…` |
| `TELEGRAM_SEARCH_TIMEZONE` | часовой пояс для «сегодня», границ дня и года в подписи |
| `TELEGRAM_SEARCH_DATE_START` | дата начала канала |
| `TELEGRAM_MEMERY_FILE` | путь к JSON со списком запощенных id |
| `TELEGRAM_SESSION_DIR` | каталог с `.session` |
| `TELEGRAM_IGNORE_AUTHOR` | необязательная: подписи авторов через запятую, посты с которыми не репостятся (старое и новое имя бота) |
| `TELEGRAM_TEST_CHAMBER_ID` | необязательная: тестовый режим. Бот шлёт в этот чат вместо канала, memery только читает (ничего не помечает опубликованным) и не ставит `reply_to`. Это id обычной группы (`PeerChat`), супергруппа не подойдёт; локальный `.env` указывает на тестовую группу, куда добавлен бот |
| `TELEGRAM_PROXY` | необязательная: прокси для обоих клиентов, `socks5://[user:password@]host:port` (также `socks4`, `http`). Нужен там, где Telegram заблокирован, например на машине разработчика в РФ (`socks5://127.0.0.1:2080`) |

## Состояние

`storage/` лежит в `.gitignore` и `.dockerignore` и монтируется в контейнер:

- `sessions/user.session` — полный доступ к пользовательскому аккаунту;
- `sessions/bot.session`;
- `memery.json` — отсортированный массив int. Если файла нет, бот пишет предупреждение и начинает с пустого списка; при первой записи файл создаётся. Запись атомарная: через `memery.json.tmp` и `os.replace`.

## Режимы и коды выхода

| Запуск | Что происходит |
|---|---|
| `python -m throwback` | обычный режим: репост в канал, запись в memery |
| то же с `TELEGRAM_TEST_CHAMBER_ID` | тестовый режим: репост в тестовую группу, memery только читается, без `reply_to` |
| `python -m throwback --dry-run` | выбор поста и печать ссылки, типов медиа и подписи; бот не логинится, ничего не отправляется и не запоминается. Пользователь только читает канал |

| Код | Значение |
|---|---|
| 0 | опубликовано (в dry-run — найдено, что опубликовать) |
| 3 | публиковать нечего: все годы перебраны |
| 1 | ошибка: неверный конфиг или любое исключение |
| 2 | неверные аргументы командной строки (argparse) |

## Сборка и запуск

- Зависимости описаны в [pyproject.toml](../pyproject.toml) и зафиксированы в `uv.lock`. Python 3.12 и локально, и в Docker.
- GitHub Actions ([build.yml](../.github/workflows/build.yml)): на каждый push и pull request запускаются `ruff check`, `ruff format --check`, `pyright` и `pytest`. Push в `main` после успешных проверок собирает образ и публикует его в `ghcr.io/<owner>/<repo>`.
- [Dockerfile](../Dockerfile): `python:3.12-slim`, зависимости ставятся через `uv sync --locked --no-dev` в `/opt/venv`, команда по умолчанию — `python -m throwback`.
- [compose.yaml](../compose.yaml): один сервис с томом `./storage`, без расписания и без restart-политики. Процесс делает один репост и завершается.
- Расписание задано вне репозитория (cron или таймер на хосте).
- Первый вход пользователем интерактивный: Telethon спросит телефон и код. Если сессия слетела, неинтерактивный запуск упадёт на `input()`.
